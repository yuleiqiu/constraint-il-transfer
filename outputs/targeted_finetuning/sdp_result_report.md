# Paired Set-Supervision Result

Status: completed development gate, 2026-07-29.

## Question

Can SDP-style policy-relative set supervision use the existing paired
corrections more effectively than positive-only behavior cloning, preserving
the injected safe-progress support without replacing successful
two-distractor task behavior?

## Fixed comparison

All learned treatments start from the epoch-260 delta-EEF checkpoint and use
the same 25 verified correction episodes, source action normalization,
learning rate `1e-5`, batch size 64, 10,000 updates, EMA evaluation, and
50/50 clean/correction sampling unless stated otherwise.

- positive BC: correction target is exactly `A+`;
- 90/10 exposure control: the same positive BC objective with 10% correction
  sampling;
- SDP: per-timestep balls
  `||a-a+|| <= 0.1 ||a+-a-||`, with `N=16` targets generated by constrained
  DDPM denoising from `K_A=16`.

SDP averages the 16 target losses within each original correction sample
before the batch mean. Thus `N` improves the Monte Carlo approximation without
silently multiplying correction exposure relative to clean rehearsal.

## Implementation and preflight

The pair loader exposes fixed-normalization positive and negative chunks and
fills clean samples with an identity negative plus a correction mask. Twelve
unit tests cover set geometry, whole-action reflection, zero-radius history,
deterministic detached target generation, clean-BC loss equivalence, pair
splits, collation, caching, and normalization.

A balanced 64-sample CUDA preflight at the paper-aligned `N=16`, `K_A=16`
passed both validation and optimizer/EMA update checks. The update used
7.96 GiB peak allocated GPU memory and 1.79 seconds; all generated targets
were inside their desired sets. The source-initialized representative batch
retained only about 2% of final single-step policy samples, but this was not a
permanent collapse to positive BC: mean final retention rose to 39% during
epoch 1 and approximately 82% on the training batches later in the run.
Held-out pair retention ended near 25%.

The 10,000-update SDP run completed successfully in approximately 37 minutes
and saved checkpoints every 1,000 updates.

## Fixed-state support

The strict diagnostic uses the same 20 source pre-collision states, 32 policy
samples per state, and a 1 cm expanded obstacle boundary.

| condition | direct safe+progress states | support-projection feasible |
|---|---:|---:|
| source | 0/20 | 1/20 |
| clean-only, 10,000 updates | 0/20 | 1/20 |
| positive BC 50/50, 10,000 updates | 10/20 | 13/20 |
| positive BC 90/10, 10,000 updates | 6/20 | 8/20 |
| SDP 50/50, 6,000 updates | 10/20 | 11/20 |

The best-Safe-SR SDP checkpoint therefore preserves nearly the full support
gain of positive BC while still causing two failure-to-success versus four
success-to-failure transitions in D2. Lower correction exposure also injects
measurable support but performs worse closed loop.

## Decision

Reject the tested paper-aligned SDP treatment and the 90/10 positive-BC
control for the fixed D2 adaptation gate, and do not launch a broad
correction-ratio or SDP-radius sweep.

This rejects one direct application of SDP, not set supervision in general.
The stronger conclusion is architectural: full-policy updates on
intervention-centered states can add the desired local action support, but
neither point targets nor policy-relative set targets tell the deployed policy
when to enter, sustain, and exit the corrective mode while preserving grasp
and placement.

The next controlled upper bound should therefore freeze the source policy and
localize adaptation explicitly: an oracle-gated correction residual or
avoidance expert with a defined handoff back to the source policy. If that
passes, replace the oracle gate with a learned obstruction/intervention gate.
This directly tests the missing mode-selection hypothesis before introducing
a world model.

Successor note (2026-07-29): the fixed SDP-6k checkpoint was subsequently
evaluated without retuning in the easier D1 transfer domain. On 100 untouched
paired layouts, equal 600-step horizons give source / SDP Task SR
`0.67 / 0.78` and CR `0.26 / 0.19`, with 12 failure-to-success versus one
success-to-failure transition. Thus this report's rejection is specific to
D2, not a universal rejection of SDP correction. See
`outputs/targeted_finetuning/d1_horizon_salvage_report.md`.
