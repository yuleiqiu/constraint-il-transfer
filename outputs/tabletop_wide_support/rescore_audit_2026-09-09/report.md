# Can the archived wide-support evaluation be rescored?

2026-09-09. User authorized inspection and a report before any rerun.
This audit used files and source only: no simulator, rendering, policy inference,
training, or new rollout was launched. Existing evaluation code was not changed.

## Finding

The archived 50-state baseline / target-lifted comparison cannot be converted
into corrected task or safe-success rates by offline relabelling. A corrected
comparison requires new execution of the 100 branches, preceded by a small
restoration / observation / outcome reproduction check. This is a recommendation,
not authorization to launch. The number of old labels actually wrong is unknown.

## Evidence

The formal condition entry point `scripts/2026-08-26_tabletop_wide_support/
raised_milk_condition_eval.py` calls `rollout_condition` without frame or chunk
callbacks and writes only aggregate JSONL rows, summary and manifest. The shared
`scripts/2026-08-05_lan_o3dp_paper_aligned/paired_eval.py` does not persist actions,
stepwise simulator states, observations, Can positions, EEF positions, or the
Python-side goal coordinates. Target displacement and minimum obstacle clearance
are scalar summaries, insufficient to reconstruct task success.

The two saved state-bank pickles each contain 50 *initial* XML/dynamic states
and metadata, not rollout histories or terminal snapshots. An inventory including
ignored files found 16 MP4s but no formal trajectory arrays/HDF5 files in the
wide-support output tree. A supplementary filename search across `outputs/` and
`/tmp/` found smoke-test metrics and older, different-policy trajectory files,
not the missing formal histories. See `inventory.json` for retained files and
the union of actual fields in each evaluated condition.

The success contract in `third_party/robosuite/robosuite/environments/manipulation/
pick_place_can_tabletop.py` requires Can XY inside the goal region, Can height
within its allowed interval, and sufficient EEF-to-Can retreat distance.
`_can_in_goal` uses Python `goal_xy`. The existing six-probe metadata audit
demonstrated a mismatch against restored goal-body coordinates; its 16/54
changed synthetic membership labels are not 16 misclassified rollouts.

Both formal evaluators terminate on the old success predicate. Actual counts:

| Archived condition | Rows | Old successes | Success stops before H600 |
|---|---:|---:|---:|
| RaisedMilk source | 50 | 29 | 29 |
| RaisedMilk target-lifted guidance | 50 | 31 | 30 |
| RaisedMilk always-on guidance | 50 | 9 | 9 |
| Clean source epoch 50 | 50 | 39 | 39 |
| Clean source epoch 250 | 50 | 23 | 23 |

Thus 59 of the 100 primary branches stopped before H600 under the old scorer.
This does **not** mean those 59 were false successes. If any was false, however,
its missing continuation cannot be recovered by relabelling. Branches that ran
to H600 also lack the per-step positions needed to detect earlier true success.

The 16 paired videos were generated by executing policies again through
`render_target_lifted_pairs.py`, not by rendering saved formal trajectories.
Their recorded task/contact/safe outcomes match the formal rows for only 9/16
source and 13/16 guided branches. They neither recover original execution nor
provide exact numerical success predicates for all 50 states. Equal seeds and
initial state hashes are therefore insufficient to salvage the comparison.

## What can be retained

The fixed state banks, checkpoint (verified present), policy parameters, original
metrics, contact identities and gradient diagnostics remain usable artifacts.
Contact flags still describe observed contact during the *old executed prefix*.
They are not automatically corrected CR: correcting the stopping time could
include additional contacts, or exclude contacts after an earlier true success.
Task/Safe/NCR and paired transitions cannot be corrected from these files.

The corrected three-layout handoff diagnostic remains separate evidence. Its
guided branches begin after a common source prefix; it cannot replace missing
full-episode rows in the original 50-state protocol.

## Minimum proposed rerun scope

- Core question, fixed current epoch-50 policy and original parameters:
  50 saved RaisedMilk states x source / target-lifted = **100 rollouts**.
- To also report corrected obstacle-free competence for that same policy:
  **50 clean rollouts** from the existing seed-827 bank. The old 39/50 cannot be
  recovered offline. This is source validation, not checkpoint reselection.
- Optional only if those historical claims are needed: **50 always-on** rows;
  **50 epoch-250 clean** rows to revisit the old checkpoint comparison.
- Reproducibility checks are additional executions, not independent layout
  samples; their scope should be fixed before the main run.

No new demonstrations, training, teacher matrix, MVEE probe or Empty2D rerun is
required by this finding. Before any execution, sync reset metadata in the
actual evaluation entry point and verify complete observations and outcomes,
not merely simulator hashes. The Sep-7 diagnostic has local synchronization;
the older formal entry points still call the affected reset path.

Future runs should persist stepwise task/contact predicate inputs, actions,
physical and metadata goal coordinates, termination reason and restoration /
randomness provenance. This enables scoring audits on the executed prefix;
it does not manufacture continuation after an early stop.
